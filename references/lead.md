# Create an onboarding message for the new developer

The supervisor runs this mode. The new developer is the reader.

Create a message from the supervisor to the new developer. Do not create a document for the supervisor. The developer will paste this message into the first `$onboarding` session.

Ask the supervisor only for information that the repository cannot provide:

1. What work must the developer do in the first two to six weeks?
2. What result will show that the developer is ready for normal tasks?
3. Which system areas will the developer own or change?
4. Which areas are unsafe or out of scope?
5. Who can answer product, code, and delivery questions?
6. What approved first task or issue should the developer use, if one exists?
7. Which documents or recent pull requests should the developer inspect?

Ask one or two questions per turn. Stop when the answers are sufficient.

Return one copyable message in the user's language. Do not create the learner's onboarding plan. Use this form:

```markdown
# Message from your supervisor

Your role:
In your first two to six weeks, I expect:
You are ready for normal tasks when:
Start with these project areas:
Do not change these areas yet:
Ask these people for help:
Read or inspect:
Approved first task:
My advice:
```

Keep the message under 250 words. Mark missing information as `Unknown`.

After the message, tell the supervisor to send it to the new developer. Tell the developer to paste it when they first run `$onboarding`.
