# What onboarding is

Onboarding increases the learner's safe independence in a real project.

The learner does not need to understand the full repository. The learner needs a small working map:

`product goal -> one system flow -> code -> test -> review -> delivery -> observation`

Use these rules:

- Teach only the knowledge needed for the next safe action.
- Start with one vertical project flow. Do not start with a directory tour.
- Use `recognize`, `operate`, and `modify` as knowledge targets.
- Check a prerequisite before teaching it. Let experienced people skip it.
- Give a beginner an easy early win before a complex project path.
- Use a small lab outside product code when a required technology is missing.
- Move from explanation to retrieval, project inspection, and a real low-risk task.
- Increase the task radius after the learner shows evidence.
- Use a buddy for company context, ownership, and decisions that the repository cannot answer.

Do not build a syllabus from every technology in the repository. Build a route to the learner's first useful task.
